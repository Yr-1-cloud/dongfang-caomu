# 06 开发规范

## 6.1 目录规范
```
com/tcm/{cfg,db,etl,qa,rag,system,utils}/   # 后端
static/{admin,rag,qa,common,coming}/        # 前端（原生 HTML/JS）
docs/{check,jiaofu,tu,kb,rag,admin,config,other}/
models/  sql/  uploads/  chroma_db/
```

## 6.2 数据库访问
- SQL 一律 `%s` 参数化，禁止字符串拼接值
- 表名/列名走白名单 `safe_table / safe_column`
- 连接用 `get_conn()` 上下文管理器：异常 rollback、finally 归还
- 插入后取自增 id 必须**同一连接**内 `cur.lastrowid`

## 6.3 路由
- 一律 `def`，不用 `async def`
- 流式用同步 generator + `StreamingResponse`

## 6.4 配置
- 所有配置走 `.env` + `cfg/settings.py`，禁止硬编码 key
- `.env` / `chroma_db/` / `models/` 不进 git

## 6.5 注释与命名
- 模块顶部写清职责；关键坑位写"为什么"而不只是"是什么"
- 表名 snake_case，接口 kebab/下划线统一

## 6.6 已知平台坑（必守）
**必须先 `import torch` 再 import langchain/langgraph**，否则 Windows 上 DLL 冲突导致段错误且无任何报错。
